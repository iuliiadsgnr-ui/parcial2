[P.01] Method

Four stages, zero guesswork.

  1. 01
    Days 1–3Async + 1 call

    Discovery & Brief

    We map business goals, audience and constraints before a single pixel: a 60-minute kickoff, a short questionnaire and a teardown of the sites you compete with.

    • Kickoff call60 min
    • Written brief1 page
    • Success metricsAgreed
    • Content inventoryShared sheet

    You get

    A one-page brief we both sign off. It becomes the yardstick for every later decision.

  2. 02
    Days 4–71 review

    Art Direction & Visual Mood

    We define the visual language: type pairing, palette, grid, motion principles and imagery direction, presented as a live mood page rather than a static PDF.

    • Mood pageLive URL
    • Type systemDisplay + text
    • Colour tokens60 / 30 / 10
    • Motion principlesEasing + timing

    You get

    A browsable direction page. Pick, mix or push back in one consolidated round.

  3. 03
    Week 21 review

    Hero Core Concept

    We design and build the hero in code at full fidelity. This is where the concept is proven: when the first screen is right, the rest follows.

    • Coded heroFull fidelity
    • BreakpointsDesktop + mobile
    • InteractionWorking prototype

    You get

    A live link to your hero. Approve it and the system is locked for the build.

  4. 04
    Weeks 2–4Final review

    Full Build & Technical Handover

    We roll the system across every page, test on real devices, tune performance and hand over clean, documented code you own outright.

    • All pagesBuilt + responsive
    • QA12 real devices
    • PerformanceLighthouse report
    • HandoverDocs + call

    You get

    Production code deployed to your host, the repository, and a recorded walkthrough.

[P.04] Revisions

Feedback, with rules.

  1. Consolidated rounds per stage

    Feedback arrives as one list per stage, from one decision-maker. It keeps momentum and avoids design by committee.

  2. A 48-hour review window

    We reply within one working day; you have 48 hours to review each milestone. Longer pauses shift the schedule, never the quality.

  3. Comments live on the work

    Notes go directly on the live preview or in Figma, so every comment has context and nothing gets lost in email threads.

  4. Approved stays approved

    Once a stage is signed off, we build on it. Reopening an approved stage is scoped as new work, so the timeline stays honest.

  5. Async first, calls when they matter

    A recorded walkthrough for every milestone; live calls for kickoff, hero review and handover.

Counts as a revision

  • Copy and content tweaks
  • Colour, spacing or type adjustments
  • Reordering or removing sections
  • Swapping images or media
  • Motion timing and easing

Counts as new scope

  • New pages or sections
  • New features or integrations
  • Changing an approved direction
  • A rebrand mid-project
  • Additional languages
